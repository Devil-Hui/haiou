# 运维总控 / 操作手则（服务器操控的统一入口）

> **这份是「舵手契约」：任何后续改动（你自己或交给 AI），都以这份文档为唯一的入口和边界。**
>
> 读这一份，就能对整套运维「改什么 / 会不会冲突 / 动完要验证什么」一目了然，**不需要**逐个翻 16 个 sh 脚本。
> 原则：**改配置不改逻辑、改文档不改已部署 unit、无 git 时先留基线再动手。**

---

## 0. 一句话总览

```
                                        ┌─ project 本体 (.env / src/ / docker-compose)  ← 业务
运维动作的落点 ──►  ops.sh 统一入口      ┤
                                        ├─ deploy/docker/*.sh  ← 被 systemd 定时调用
                                        └─ deploy/doctor/*.sh   ← 手动体检/状态/init
```

- **统一入口**：`bash deploy/ops.sh <子命令>` 一个命令分发到所有脚本；加 `--dry-run` 就是**断点测试**（只打印要跑什么，不执行）。`bash deploy/ops.sh list` 列全部子命令。
- **业务代码**：`src/`、`.env`、`docker-compose*.yml` —— 更新不影响运维，运维也不影响它。
- **运维脚本**：`deploy/docker/*.sh`、`deploy/doctor/*.sh` —— 更新安全（systemd 只"引用脚本路径"，不嵌逻辑）。
- **调度**：`deploy/docker/systemd/*` —— 这是**唯一真正的危险区**，守则见 §3。
- **物理位置不动**：`ops.sh` 只做转发，不搬动任何脚本——4 个 systemd 定时器硬编码引用 `deploy/docker/*.sh`，搬动会破坏已装 unit。

## 1. 全境地图（谁在几点、跑什么、数据落哪）

### 1.1 定时任务（宿主机 systemd timer，每日/每月自动）

| systemd unit（源文件在 `deploy/docker/systemd/`） | 时间（源文件 `OnCalendar`） | 调用脚本 | 干什么 | 落盘 |
|---|---|---|---|---|
| `aura-docker-backup.timer` | 每天 `03:30` | `backup.sh` | 全量备份 DB，保留 14 天 | `data/backups/db/*.dump*` |
| `aura-docker-restore-check.timer` | 每月 1 日 `04:30` | `restore-check.sh` | 还原演练，验证备份可用 | 临时库即造即删 |
| `aura-docker-maintenance.timer` | 每 5 分钟 | `maintenance.sh` | 订单过期/充值推进/凭证抹除 | 仅 DB 操作 |
| `aura-docker-log-prune.timer` | 每天（凌晨） | `log-prune.sh` | 清理容器日志 | `data/logs/` |

> **改时间**：只改 `deploy/docker/systemd/<unit>.timer` 源文件的 `OnCalendar` 一行，
> 然后重装 `bash deploy/docker/fix-crlf.sh --install`（会自动 LF 化 + 替换路径）。
> **绝不要**直接 `systemctl edit` 去改已 `/etc/systemd/` 里的副本——下次 `--install` 会覆盖回去。

### 1.2 手动工具（按需跑，不占定时）

| 命令 | 做什么 | 安全门 |
|---|---|---|
| `bash deploy/doctor/init.sh` | 首装向导 | 需 root |
| `bash deploy/doctor/aura-doctor.sh` | 全量体检（db / admin / connect / **ports** / cloudflare） | 需安全门 |
| `bash deploy/doctor/aura-doctor.sh --only=ports` | 端口开放&安全暴露核查（监听面 / 防火墙 / 安全组 / db 5432 是否裸公网） | 需安全门 |
| `bash deploy/doctor/status.sh` | 运维面板（备份新鲜度/数据目录/端口/磁盘） | 需安全门 |

> **🧭 统一入口 `deploy/ops.sh`**：以上所有手动命令都可用 `bash deploy/ops.sh <别名>` 一键触发，
> 并支持**断点测试**（`--dry-run` 只打印将执行什么、不运行）。速查：
>
> ```bash
> bash deploy/ops.sh list                 # 列出全部子命令
> bash deploy/ops.sh --dry-run backup     # 【断点】只看要跑什么，不执行
> bash deploy/ops.sh doctor --only=ports  # 只跑端口安全体检
> bash deploy/ops.sh ports                # 同上（别名）
> bash deploy/ops.sh status               # 运维面板
> bash deploy/ops.sh log-prune            # 清日志（DRY_RUN=1 只看）
> ```
> `ops.sh` 是**纯转发层**（stdout 与子脚本一致、信息日志走 stderr，
> 退出码透传；子脚本的安全门/错误码**不被绕过**）。不搬动脚本（systemd 仍直连 `deploy/docker/*.sh`）。
>
> ⚠️ **dry-run 的边界**：`ops.sh --dry-run xxx` 只做到**转发层**——打印「将运行 bash xxx」而不执行。
> 它**不模拟** `backup.sh` 内部的动作。要子脚本自己「假跑」看效果，用子脚本自带的开关，
> 例如 `log-prune` 的 `DRY_RUN=1`（见 §6.1）。分清两层的 dry-run 才不会被误导。
| `bash deploy/doctor/logs.sh` | 看日志 | 需安全门 |
| `bash deploy/doctor/secure-user.sh [--apply]` | 建受限用户跑 docker（安全增强） | 需 root |
| `bash deploy/docker/restore-check.sh` | 立即恢复演练 | — |

### 1.3 数据目录（都在 `data/`，权限固定 0700）

| 目录 | 属主 | 用途 |
|---|---|---|
| `data/postgres` | root（PG 容器） | 数据库物理文件 |
| `data/backups/db` | 运行用户 | 每日备份 .dump + .sha256（=3-2-1 第一份） |
| `data/logs` | **1000:1000** | 容器日志（Nginx/app 写的用户 uid=1000） |
| `data/doctor` | 运行用户 | 体检状态/安全门/backup.state |

> **位置不可达时的友好提示**：拿错误码去 §5 反查「该在哪建」。
> 例如 `MF_001`=缺目录 → 末尾已给 `mkdir -p "<完整路径>" && chmod 0700 "<完整路径>"`。

## 2. 你想改一件事 → 动谁（改动最小对照表）

> 这是"我改个东西，该碰哪个文件、会不会影响别人"的最短路径。

| 你想做 | 改谁 | 别碰 | 改完验证 |
|---|---|---|---|
| 备份时间 / 保留天数 | `.env` 或 systemd `.timer`/`.service` 的 `OnCalendar`/`KEEP_DAYS` | `backup.sh` 逻辑 | `bash deploy/doctor/status.sh` 看最新备份 |
| 离机转移（rsync/rclone） | `.env` 配 `OPS_OFFSITE_TRANS` | 无 | 手工先跑一次确认文件真到远端 |
| 数据库备份**方式/格式** | `backup.sh`（pg_dump 参数那几行） | systemd unit | `bash -n backup.sh` + 手工跑一次 |
| 日志清理策略（保留时长） | `.env` 或 `log-prune.sh` 顶部的阈值 | 无 | `bash -n log-prune.sh` |
| 加一条体检项 | 新增 `deploy/doctor/checks/mychk.sh` +（可选）在 `aura-doctor.sh` 加 `run_block` | 别改 engine | `aura-doctor.sh --only=mychk` |
| 看备份是否停摆 | 只读：`status.sh`（读 `data/doctor/backup.state`） | — | — |
| 核查端口开放/暴露 | 只读：`status.sh`（面板粗看）或 `aura-doctor.sh --only=ports`（全量：监听面+防火墙+安全组+db 5432 暴露） | — | `ports` 检项目前为只读，输出即结论 |
| 改 Cloudflare 回源端口 | `.env` 的 `NGINX_CF_GUARD_PORT` | `checks/ports.sh` | `aura-doctor.sh --only=ports`（自动读 .env 覆盖） |

## 3. 更新安全地图（会冲突 / 不会冲突）

| 类别 | 更新有风险？ | 说明 |
|---|---|---|
| `deploy/docker/*.sh`（backup/restore/maintenance/log-prune） | ✅ 无冲突 | systemd unit 只**调用脚本路径**，不内嵌脚本逻辑；改 shb 不影响定时器，定时也不覆盖你的改动。 |
| `deploy/doctor/*.sh` | ✅ 无冲突 | 纯手动工具，无任何宿主机定时器。 |
| `deploy/docker/systemd/*` | 🔴 **唯一高危区** | 被 `fix-crlf.sh --install` 读源、替换路径后安装到 `/etc/systemd/system/`。**改动必须改源文件 + 重新 install**；手动改了 `/etc/` 副本会被下次 install 覆盖。 |
| `src/`、`.env`、`docker-compose*.yml` | ✅ 无冲突 | 业务层与运维层互不相通。做运维不要动应用代码；动应用代码不要带 MDM per ops。 |
| `docs/*.md` | ✅ 无冲突 | 纯文档。 |

**最重要的真相：本项目无 git 仓库。** 更新 `deploy/` 前没有基线，误改无法 `git diff` 回滚。
→ **动手前先留一份快照**（见 §5）。

## 4. OPS 错误码定位表（现象 → 码前缀 → 本地反查）

> 约定：`OP_{拼音缩写}_{3位序号}`。取**前两字母拼音**即锁大类，尾号定位具体位置。
> 与业务 HTTP ErrorCode（`src/lib/core/api-error.ts`）分层，互不干预。

| 前缀 | 拼音 | 含义 | 落地位置 |
|---|---|---|---|
| `MF` | muFen | 目录/路径 缺 | `engine.sh`、`backup.sh`、`log-prune.sh` |
| `QX` | QuanXian | 权限不足 / 不可写 | `engine.sh`、`backup.sh` |
| `BF` | BeiFen | 备份 | `backup.sh` |
| `SJ` | ShJu | 数据库 | `restore-check.sh` / db 检查 |
| `QL` | QingLi | 清理/删除 | `log-prune.sh` |
| `WL` | WangLuo | 网络/连通 | `checks/connect.sh` |
| `DK` | DuanKou | 端口/监听面/暴露 | `checks/ports.sh`（**只读**，输出即结论，暂无数字码） |
| `YZ` | YanZheng | 校验/依赖缺失 | `engine.sh` |
| `ZT` | ZhuangTai | 状态文件 | `status.sh` |
| `QY` | QianYi | 迁移/转移 | 预留（离机转移） |
| `HF` | HuiFu | 恢复/还原 | `restore-check.sh` |

**现象 → 怎么定位**：报告里看到 `xx_001` 之类 → 前缀对上面 → 去对应脚本 grep 该码 → 它通常在 `ops_fail <码> <标题> [修复命令]` 里，**末尾必有「该去哪建/怎么修」的命令**。

> ⚠️ **以代码为准**：本表列出的是**类别前缀**（含预留）。当前**真实会发出**的数字码只有 4 个：`MF_001`、`QX_001`、`YZ_001`（`engine.sh` 的 `ops_fail`）、`QL_001`（`log-prune.sh` 的 `printf`）；backup.sh 缺目录/不可写也发 `MF_001`/`QX_001`。
> `BF_`、`WL_`、`SJ_`、`DK_`、`HF_`、`QY_`、`ZT_` 目前只是 `engine.sh` 注释里的约定/预留（`BF_001`/`WL_002` 是示例写法，**代码未真正发过**，别去对应脚本里找）。
> 排查用 `grep -rnE '\b[A-Z]{2}_[0-9]{3}\b' deploy/` 拿全量真实发码点。

## 5. 无 git 时的安全改法（动手前必做）

```bash
# 1.(一次)建一份「基线」副本 —— 未来 diff 的参照
cd <项目根> && tar czf /tmp/aura.deploy.baseline.$(date +%F).tgz deploy/
# 2.改动 deploy/ 前
tar czf /tmp/aura.deploy.prefix.$(date +%F_%H%M).tgz deploy/
# 3.改动后核对
ls -l /tmp/aura.deploy.*.tgz           # 确认两版都在
# 4.(可选) 用 diff 看这次到底动了哪
diff <(tar tzf /tmp/aura.deploy.prefix.*.tgz) <(tar tzf /tmp/aura.deploy.baseline.*.tgz) | head
```

> 长期建议：给项目 `git init` 一次（若坚持不用 git，就用上面的归档法）。git 是拿 diff/回滚 的唯一可靠基线，不引入远程、不外传任何敏感项，只在本地 `.gitignore` 掉 `data/` 与 `.env`。

## 6. 参数集中改（面向未来的「面板⇄服务器全文联动」）

> 现在大部分运维参数仍硬编码在脚本顶部（`KEEP_DAYS=14`、`OnCalendar=03:30` 等）。
> 想少改脚本的后续方向——把它们抽成一个运维配置：

- `deploy/ops.conf`（键值/INI，由 `backup.sh`/`log-prune.sh` 等 `source` 读取）
  - `BACKUP_KEEP_DAYS=14`
  - `BACKUP_SCHEDULE="*-*-* 3:30:00"`  ← 仅供文档，实际由 systemd timer 消费
  - `LOG_PRUN_MAX_KEEP_DAYS=14`
  - `OPS_OFFSITE_TRANS=...`
  - `OPS_STATE_DIR=${APP_ROOT}/data/doctor`

### 6.1 现在已经能改的（不用碰脚本）

| 想改 | 在项目根 `.env` 加一行 | 生效 |
|---|---|---|
| 备份保留天数 | `KEEP_DAYS=30` | 下次备份即生效 |
| 备份目录位置 | `BACKUP_DIR=/mnt/disk2/aura-backup` | 同上 |
| 离机转移命令 | `OPS_OFFSITE_TRANS="rsync -az --delete <项目根>/data/backups/db/  backup@远端:/backup/aura/"` | 每次备份后执行 |
| 日志 app 保留 | `LOG_KEEP_APP=7` | 下次清理 |
| 日志审计保留 | `LOG_KEEP_AUDIT=730` | 下次清理 |
| 日志 error 保留 | `LOG_KEEP_ERROR=30` | 下次清理 |
| 日志支付保留 | `LOG_KEEP_PAYMENT=180` | 下次清理 |

> **离机转移实战备注**：
> - `backup.sh` 支持「全量 + `--delete` 增量镜像」到远端；**本地第一份永远不清**（3-2-1）。
> - **容器里没有备份文件**（备份本来就落宿主 `data/backups/db`），所以"转完清容器"不适用。
> - **离机命令配完，务必手工先跑一次**确认文件真到远端——否则"以为备份了"最致命。

### 6.2 建议分两阶段收敛

1. **现在**：保持脚本内 `env 变量 + 默认值`（已这样做：`BACKUP_DIR`/`KEEP_DAYS`/`OPS_OFFSITE_TRANS`/`LOG_KEEP_*` 都是环境变量，`.env` 可覆盖）。想改就 `.env` 加一行。
2. **以后**：把非 `BACKUP_`/`LOG_KEEP_` 系的运维项（如定时 `ON_CALENDAR`、清理阈值）集中到 `ops.env`，并把 `fix-crlf.sh --install` 升级为「从 `ops.env` 生成 timer 的 `OnCalendar`」。**别现在做**——动 systemd 生成逻辑风险最高，收益在参数多起来之后才划算。

## 7. 联动与未来（面板 ⇄ 服务器 ⇄ 调度）

现状已具备的内置联动：

- **备份 → 状态**：`backup.sh` 每次写 `data/doctor/backup.state`（generated_ts/latest/size/offsite）；
  `status.sh` 读它 + 48h 新鲜度检查 → 备份停摆会被标红。
- **体检 → 指令**：`aura-doctor.sh` 把每项"未配置"项展开成一条可执行 fix 命令。任何后续 AI 可让 doctor 先跑一遍，把 `-missing` 项当作操作清单。

**后续可优化的面板方向（你最想要的那层）**：
1. 把 `status.sh` 输出走 JSON（`--json`），让监控/面板直接消费。
2. `backup.state` 追加 `next_due`、`last_exit`，面板能显示"下次 03:30 又要跑"。
3. （可选）一个 `ops.sh --cmd=<backup|prune|status|doctor>` 总入口，把"点某个按钮 → 跑某脚本 → 回读某个状态文件"封装，成为真正的"通过控制面板间接操控服务器"。
